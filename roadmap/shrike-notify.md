## P2/P3 — v1-completion gaps found by code inspection (2026-09-11)
- [ ] [P2] [ready] Gate GET /tokens and POST /tokens/revoke behind require_auth — currently in `backend/app/routers/messages.py`, `list_tokens()` and `revoke_token()` have no auth dependency at all (unlike `publish`/`subscribe`, which use `require_topic_and_auth`), so even with NOTIFY_REQUIRE_AUTH=1 any unauthenticated caller can GET /tokens and dump every active bearer token, or POST /tokens/revoke to invalidate someone else's token. Add an auth check (e.g. require a valid `scope="*"` token) to both endpoints when settings.require_auth is true, and add a regression test in `backend/tests/test_tokens_api.py` asserting 401 without a wildcard token. {cat: backend; size: S; multifile: no; research: none}
- [ ] [P2] [ready] Wire the already-built TokenStore into token issue/revoke so persistence is consistent with messages — `backend/app/persistence.py` has a fully implemented and unit-tested `TokenStore` (create_token/get_tokens_for_user) but it is never called from `backend/app/services/auth.py` or the NOTIFY_PERSIST startup hook in `backend/app/main.py` (which only wires up MessageStore). Result: with NOTIFY_PERSIST=1, message history survives a restart but the issued-token registry and revoked-token deny-list do not — a revoked token becomes valid again after a restart. Wire TokenStore the same way MessageStore is wired in `startup_check()`, and add a test mirroring `test_broker_with_attached_store_persists_across_a_fresh_broker_instance` for tokens. {cat: backend; size: M; multifile: yes; research: none}
- [ ] [P3] [ready] Make NOTIFY_MAX_MESSAGE_LENGTH actually control the publish body limit — `backend/app/config.py`'s `Settings.max_message_length` (env NOTIFY_MAX_MESSAGE_LENGTH, default 4096) and `backend/app/models.py`'s `truncate_body()` helper are both dead code: `PublishRequest.body` in `backend/app/schemas.py` uses a hardcoded `Field(..., max_length=4096)`, so changing the env var has zero effect on what the API accepts. Replace the static Field constraint with a validator that reads `get_settings().max_message_length` (or otherwise wires the setting through), and add a test in `backend/tests/test_schemas.py` that changing NOTIFY_MAX_MESSAGE_LENGTH changes the accepted body length. {cat: backend; size: S; multifile: no; research: none}
