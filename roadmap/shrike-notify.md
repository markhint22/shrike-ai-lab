## P2/P3 — v1-completion gaps found by code inspection (2026-09-11)
- [ ] [P2] [decomposed] Gate GET /tokens and POST /tokens/revoke behind require_auth — currently in `backend/app/routers/messages.py`, `list_tokens()` and `revoke_token()` have no auth dependency at all (unlike `publish`/`subscribe`, which use `require_topic_and_auth`), so even with NOTIFY_REQUIRE_AUTH=1 any unauthenticated caller can GET /tokens and dump every active bearer token, or POST /tokens/revoke to invalidate someone else's token. Add an auth check (e.g. require a valid `scope="*"` token) to both endpoints when settings.require_auth is true, and add a regression test in `backend/tests/test_tokens_api.py` asserting 401 without a wildcard token. {cat: backend; size: S; multifile: no; research: none}
- [ ] [P2] [decomposed] Wire the already-built TokenStore into token issue/revoke so persistence is consistent with messages — `backend/app/persistence.py` has a fully implemented and unit-tested `TokenStore` (create_token/get_tokens_for_user) but it is never called from `backend/app/services/auth.py` or the NOTIFY_PERSIST startup hook in `backend/app/main.py` (which only wires up MessageStore). Result: with NOTIFY_PERSIST=1, message history survives a restart but the issued-token registry and revoked-token deny-list do not — a revoked token becomes valid again after a restart. Wire TokenStore the same way MessageStore is wired in `startup_check()`, and add a test mirroring `test_broker_with_attached_store_persists_across_a_fresh_broker_instance` for tokens. {cat: backend; size: M; multifile: yes; research: none}
- [ ] [P3] [decomposed] Make NOTIFY_MAX_MESSAGE_LENGTH actually control the publish body limit — `backend/app/config.py`'s `Settings.max_message_length` (env NOTIFY_MAX_MESSAGE_LENGTH, default 4096) and `backend/app/models.py`'s `truncate_body()` helper are both dead code: `PublishRequest.body` in `backend/app/schemas.py` uses a hardcoded `Field(..., max_length=4096)`, so changing the env var has zero effect on what the API accepts. Replace the static Field constraint with a validator that reads `get_settings().max_message_length` (or otherwise wires the setting through), and add a test in `backend/tests/test_schemas.py` that changing NOTIFY_MAX_MESSAGE_LENGTH changes the accepted body length. {cat: backend; size: S; multifile: no; research: none}
- [ ] [P3] [decomposed] Delete domain-irrelevant orphaned utility modules with zero call sites — `backend/app/utils/mask_phone.py`, `is_valid_email.py`, `format_bytes.py`, `pluralize.py`, `flatten.py`, `coalesce.py`, `backoff.py`, `dedupe.py`, `topic_slug.py`, and `truncate.py` are each fully unit-tested (matching `backend/tests/test_*.py` files) but have zero call sites anywhere in `app/routers/`, `app/services/`, `app/schemas.py`, `app/models.py`, or `app/main.py` (verified via repo-wide grep) — a phone-masking/email-validation/byte-formatting/pluralization grab-bag unrelated to a topic-based pub/sub notifier. Per the roadmap's "do NOT overbuild ... freeze to maintenance" directive, delete the 10 source files and their matching test files (re-grep immediately before each deletion to confirm no last-minute caller appeared). {cat: backend; size: S; multifile: yes; research: none}
- [ ] [P3] [decomposed] Remove the dead duplicate TTL-expiry implementation before freeze — `backend/app/utils/ttl.py::is_expired(message_created_at: datetime, ttl_seconds)` is a second, differently-signatured implementation of the same check as the actually-wired `backend/app/services/ttl.py::is_expired(msg_ts: float, ttl_s, now_ts)`, which `Broker._purge_expired_and_capped()` in `backend/app/services/broker.py` calls. `backend/tests/test_ttl.py` tests both side by side, but only the `services.ttl` version has a production caller. Two same-named `is_expired` functions with different signatures is a landmine for whoever touches TTL logic after the v1 freeze. Delete `backend/app/utils/ttl.py` and trim `test_ttl.py` down to just the `services.ttl` coverage. {cat: backend; size: S; multifile: yes; research: none}

## P1/P2/P3/P4 — new gaps found by code inspection (2026-09-14, fleet dry-run refuel)
- [ ] [P1] [decomposed] Fix phantom `get_token_store` import crashing persisted-auth wiring — `backend/app/dependencies.py::get_auth_manager()` (lines ~91-95) does `from app.persistence import get_token_store` then `await get_token_store(settings.database_url)`, but `backend/app/persistence.py` defines no such function (grep for `def get_token_store` across `app/` returns zero hits — only the `TokenStore` class exists there), so resolving `get_auth_manager` with `settings.persist=True` raises `ImportError` immediately; it's untested (no test in `backend/tests/test_dependencies.py` or elsewhere calls `get_auth_manager`). Add a `get_token_store(database_url)` factory to `backend/app/persistence.py` that constructs and `await`s `.init()` on a `TokenStore` (mirroring how `backend/app/main.py::startup_check()` builds `MessageStore`), and add a regression test in `backend/tests/test_dependencies.py` that calls `get_auth_manager(Settings(persist=True))` and asserts it returns a working `AuthManager` instead of raising. {cat: backend; size: M; multifile: yes; research: repo}
- [ ] [P1] [decomposed] Fix `is_expired()` signature/type mismatch vs. its only caller — `backend/app/services/ttl.py::is_expired(message_created_at: datetime, ttl_seconds: int)` takes exactly 2 params and a `datetime`, but its only real caller, `backend/app/services/broker.py::Broker._purge_expired_and_capped()`, calls `_is_expired(m.created_at, self.ttl_seconds, now_ts)` — 3 positional args, with `m.created_at` a `float` epoch timestamp (per `backend/app/models.py::Message.created_at: float`). This raises `TypeError: is_expired() takes 2 positional arguments but 3 were given` the moment `Broker.ttl_seconds` is ever > 0; it's currently uncaught because `backend/tests/test_broker.py` has zero tests exercising TTL expiry. Change `is_expired`'s signature to `is_expired(msg_ts: float, ttl_seconds: int, now_ts: float) -> bool` to match the caller, update `backend/tests/test_ttl.py`'s datetime-based assertions to the new float-timestamp shape, and add a test mirroring the exact 3-arg call used in `broker.py`. {cat: backend; size: M; multifile: yes; research: repo}
- [ ] [P2] [decomposed] Close token-revocation authorization gap on POST /tokens/revoke — `backend/app/routers/messages.py::revoke_token()` only depends on `Depends(get_current_user_scoped)` (accepts any valid bearer token, or an unauthenticated `ScopedUser(scope="*")` when `NOTIFY_REQUIRE_AUTH=0`), unlike `list_tokens()` in the same file which requires `Depends(require_wildcard_token)` from `backend/app/security/scope.py`. Since `backend/app/services/auth.py::revoke_token(token)` never checks the caller's own scope against the token being revoked, any caller holding a token scoped to one topic can revoke ANY other issued token string (including another caller's wildcard token) just by knowing it. Change `revoke_token()`'s dependency to `Depends(require_wildcard_token)` to match `list_tokens`, and add a regression test in `backend/tests/test_tokens_api.py` asserting a non-wildcard-scoped bearer token gets 401 on `POST /tokens/revoke` when `NOTIFY_REQUIRE_AUTH=1`. {cat: backend; size: S; multifile: no; research: repo}
- [ ] [P2] [decomposed] Delete the duplicate QuietHoursConfig/should_defer_delivery landmine in `backend/app/utils/quiet_hours.py` — this module defines its own `QuietHoursConfig` dataclass (fields: `start`, `end`) plus `should_defer_delivery(dt, config)`/`is_within_quiet_hours(dt, config)`, which duplicate-but-differ from `backend/app/config.py::QuietHoursConfig` (fields: `start`, `end`, `timezone`, used by the actually-wired `backend/app/services/broker.py::should_deliver_now(message, config)`) and from `backend/app/delivery.py::should_defer_delivery(dt, quiet_start, quiet_end)` (separate int args, used by `DeliveryManager.deliver_message`). Two same-named `QuietHoursConfig` classes with different fields and two same-named `should_defer_delivery` functions with incompatible signatures is the exact landmine shape already fixed once for `is_expired` (see the completed TTL dedup item above) — importing the wrong one silently drops the `timezone` field or breaks call sites. Delete `backend/app/utils/quiet_hours.py`'s `QuietHoursConfig` class and its `should_defer_delivery`/`is_within_quiet_hours` wrappers (keep `in_quiet_hours()`, the shared primitive both `app/delivery.py` (line 2 import) and `app/services/broker.py` (line 26 import) actually use), and trim `backend/tests/test_quiet_hours.py` down to just `in_quiet_hours()` coverage plus one new test importing `QuietHoursConfig` from `app.config` to confirm the canonical one still works. {cat: backend; size: S; multifile: yes; research: repo}
- [ ] [P3] [decomposed] Evict expired/revoked entries from the in-memory `_issued_tokens` registry — `backend/app/services/auth.py::register_token()` adds every issued token to the module-level `_issued_tokens: dict[str, tuple[str, int, int | None]]` dict (line 106) and nothing ever removes an entry: not on expiry, not on `revoke_token()`. `get_active_tokens()` only filters at read time via `is_revoked()`/`expires_at` checks — it never prunes the backing dict, so a long-running process handing out even short-TTL tokens leaks memory indefinitely. This is the same unbounded-growth shape that `backend/app/services/ratelimit.py::RateLimiter._maybe_evict_idle()` already solves for its `_buckets` dict (per that class's own docstring warning about unbounded growth from throwaway keys). Make `revoke_token()` also pop the token from `_issued_tokens`, and have `get_active_tokens()` delete (not just skip) entries whose `expires_at` has passed, then add regression tests in `backend/tests/test_auth.py` asserting `_issued_tokens` shrinks after a token is revoked and after it expires. {cat: backend; size: S; multifile: no; research: repo}
