## P2 — content + progression (~q2-3)
- [ ] [P2] [decomposed] Mission variety + campaign arc — Adopt Into the Breach's model: a small fixed set of ~6 objective types (Protect/Escort, Destroy Target, Hold Position N turns, Extract Before Timer, Non-Lethal/Don't-Kill using existing suppression predicates, Survive Escalating Waves) combined with varying hand-authored terrain/enemy layouts, since combinatorial reuse of few objective types is what lets a solo dev generate real variety without a mission generator. Structure the campaign as a short linear "chapter" spine (3 acts x ~5 missions, Wildermyth-style) with occasional binary branch points offering a choice of one of two hand-authored missions per branch, giving light replayability without doubling total authored content. Add win/lose variety beyond kill-all: partial success (objective met but with losses = degraded reward), hard mission-failure on timer/objective-death, and permanent unit loss carrying into the campaign to raise stakes. {cat: game; size: L; multifile: yes; research: none — completed 2026-09-10, sources: Into the Breach (intothebreach.fandom.com), Wildermyth campaign structure (wildermyth.com/wiki/Campaign)}
- [ ] [P2] [decomposed] Roster depth: classes, abilities, synergy, upgrades — Ship 4-6 mechanically distinct classes tied directly to xlite's existing combat predicates rather than a generic RPG job system: Vanguard (melee/flanking specialist), Sentinel (overwatch/suppression specialist), Support (heal/buff/reposition), and Saboteur (destructibles/terrain control), each with 2-3 active abilities and one passive, following Fell Seal's lean "2 passives + abilities per class" scope rather than XCOM's deeper per-class trees. Design synergy explicitly as two-ability combos across classes (Mario+Rabbids pattern: one ability sets up, another cashes in) — e.g. Saboteur destroys cover to open a flank lane for Vanguard, or Sentinel's suppression guarantees Vanguard's flanking bonus on the same target. Upgrades are a flat per-class perk list (not subclassing/multiclassing) of ~3-4 tiers and ~10-12 total unlocks per class, gated by a mission-completion currency (not grindable XP) to keep authoring and balance small enough for one dev. {cat: game; size: L; multifile: yes; research: none — completed 2026-09-10, sources: Fell Seal: Arbiter's Mark classes (fellseal.fandom.com/wiki/Classes), Mario + Rabbids Kingdom Battle weapon synergy (news.ubisoft.com)}

## P3 — ship + mobile (~year 2)
- [ ] [P3] [decomposed] Desktop release (Steam/itch) prep — Steam: create Steamworks account, pay the $100 Steam Direct fee (refundable after $1,000 gross revenue), then plan for a mandatory 30-day store-page-live period before release (realistic 4-6 week runway); build 5 required capsule assets (Header 920x430 is mandatory, plus Small/Main/Vertical/Library) plus 5+ screenshots at 1920x1080 and a 60-90s trailer leading with gameplay. Achievements/cloud-saves need GodotSteam, but note it was archived (read-only) July 2026 — verify it still builds against the current Godot 4.x export template before committing to it, or ship without Steam features first via itch.io (butler CLI upload, no fee, no wait) as the low-risk first release. {cat: infra; size: M; multifile: no; research: none — completed 2026-09-10, sources: datahumble.com Steam Direct 2026 guide, GodotSteam GitHub (archived), itch.io butler docs}
- [ ] [P3] [decomposed] Mobile port (Android first) — touch controls, safe-area — Remap desktop trackpad pinch-zoom/click-drag-pan to native two-finger pinch and one-finger drag on Camera2D (proven pattern: community PinchPanCamera / godot-touch-camera-2d assets), tap-to-select/tap-to-move for unit control since turn-based play has no real-time input-latency risk; use Godot's `DisplayServer.get_display_cutouts()` / `get_window_safe_area()` to keep the tactics HUD off notch/cutout regions rather than hand-rolled offsets. Biggest gotcha: Google Play now requires target API level 35 (Android 15) for all new submissions and AAB format, plus a mandatory Data Safety form (required even if xlite collects zero user data) — confirm the Godot Android export template + installed SDK/JDK17 toolchain are current before building, since template/API-level mismatches are the most common indie rejection cause. {cat: game; size: L; multifile: yes; research: none — completed 2026-09-10, sources: Android Developers target-sdk requirements, Godot Android export docs (developer.android.com/games/engines/godot)}
